# PZSA-2026-002: typicms/core 17.0.0 to 17.0.46: stored cross-site scripting in the JSON-LD block of public pages

## Summary

[TypiCMS](https://github.com/typicms/core) is a multilingual content management system built on Laravel and distributed as the Composer package `typicms/core`. The JSON-LD component rendered on every public page embeds the page title and meta description with `json_encode()` inside a `<script type="application/ld+json">` element without the `JSON_HEX_TAG` flag. A page title containing `</script>` therefore terminates the data block, and what follows is executed as script in the browser of every visitor of that page. An account with the `create pages` or `update pages` permission is enough. Fixed in 17.0.47.

## Affected versions

- 17.0.45, verified on a local installation (commit ed20bda9).
- The component was introduced in 17.0.0 (commit ef6c0d8b, 2026-03-06) with the same flags; 17.0.0 to 17.0.44 were not tested individually. 16.x has no JSON-LD component.
- 17.0.46 is still affected (it only contains the fix for PZSA-2026-001). Fixed in 17.0.47 (commit 1b171b87a7d5, 2026-11-05).

## Methodology

Source review of typicms/core at commit ed20bda9 (release 17.0.45), followed by dynamic testing on a local installation of 17.0.45 with the default configuration: the title of a page was set from the back-office with a user holding `update pages`, and the public page was then loaded in a browser as an anonymous visitor.

## Technical analysis

- `resources/views/public/components/json-ld.blade.php` prints `json_encode($schema, JSON_UNESCAPED_SLASHES | JSON_PRETTY_PRINT)` through the unescaped `{!! !!}` Blade syntax. Neither `<` nor `>` is encoded.
- `resources/views/public/components/layouts/page.blade.php` passes `$page->title` and `$page->meta_description` into the schema.
- `src/Http/Requests/PageFormRequest.php` validates the title only for length.
- The back-office layout prints the current user's API token in a `<meta name="api-token">` element. Script running in the site origin can fetch a back-office page with the victim's cookies and read that token when the victim is logged in, which turns the XSS into full API access as that user (see PZSA-2026-001 for what the token allows). This chain was established by source analysis and is the reason the report was filed as High.

## Impact

A content editor can run arbitrary script in the browser of every visitor of a public page, including administrators. Consequences range from defacement and phishing to the theft of an administrator's API token.

CVSS rationale: PR:L because the attacker needs an account that can create or update pages; UI:P because the victim only has to load the page. The script runs in the visitor's browser, which is scored as the subsequent system (SC:L, SI:L); the base score is the conventional stored-XSS score and does not include the token-theft chain described above.

## Proof of concept

Set the English title of a page to the following value, save, and open the page as any visitor:

```
</script><script>document.title='XSS on '+document.domain</script>
```

The document title changes, which shows that script from the title field runs in the page.

## Remediation

17.0.47 changes the `json_encode()` call to `JSON_HEX_TAG | JSON_HEX_AMP | JSON_UNESCAPED_SLASHES | JSON_PRETTY_PRINT`, so `<`, `>` and `&` are emitted as `<`, `>` and `&` and the script element cannot be closed from the data. Upgrade to 17.0.47 or later.

For installations that cannot upgrade, the patch supplied with the report (`PZSA-2026-002/0002-Escape-HTML-significant-characters-in-JSON-LD-output.patch`) applies the same change plus `JSON_HEX_APOS | JSON_HEX_QUOT`; a regression test (`PZSA-2026-002/JsonLdEscapingTest.php`) is included.
