# PZSA-2026-004: keystone (keystone-classic) 4.0.0 to 4.2.1: CSV export does not neutralise values starting with `+` (incomplete fix for CVE-2017-15879)

> Identifier in the report sent to the maintainers: KS-002.

## Summary

The npm package `keystone` 4.x (Keystone "classic") is a Node.js content management system and web application framework, archived by the maintainers in February 2022 and superseded by Keystone 6 (`@keystone-6/core`), a different code base that is not affected. The CSV export of the Admin UI prefixes cell values that start with a formula trigger with a space, a protection introduced for CVE-2017-15879. Because of an off-by-one comparison, values that start with `+` are returned unchanged, so a string stored in any exported list can become a formula when a staff member opens the export in a spreadsheet application. There is no fixed version; a patch and mitigations are provided.

## Affected versions

- 4.2.1 (npm), verified; identical to commit 6e5ba1142 of keystonejs/keystone-classic.
- Every release that contains `lib/security/escapeValueForExcel.js` (introduced by PR #4478, merge f08baa4f, 2017) is believed affected, not individually tested.
- No fixed version: the repository was archived in February 2022.

## Methodology

Source review of keystone-classic at commit 6e5ba1142, identical to npm 4.2.1. The behaviour of `escapeValueForExcel()` was confirmed by calling the function in isolation (see Proof of concept). Not reproduced on a running instance.

## Technical analysis

The trigger list and the check in `lib/security/escapeValueForExcel.js` are:

```js
const formulaTriggers = ['+', '-', '=', '@'];
function escapeValueForExcel (value) {
	if (formulaTriggers.indexOf(value.toString().slice(0, 1)) > 0) {
		return ' ' + value;
	}
	return value;
}
```

`Array.prototype.indexOf` returns `0` for the first element, and `0 > 0` is false. Values whose first character is `+` are therefore returned unchanged, while `-`, `=` and `@` are escaped as intended. `+` is a recognised formula prefix in Microsoft Excel and LibreOffice Calc, so the protection introduced for CVE-2017-15879 has a one-character hole.

Data path:

- `GET /<admin path>/api/:list/export.csv` (`admin/server/app/createDynamicRouter.js:92`, handler `admin/server/api/list/download.js`) calls `req.list.getCSVData()` for every matching item.
- `getCSVData()` flattens the item (`lib/list/getCSVData.js:95-112`) and then runs each cell through `escapeValueForExcel` (`:114-117`). No other escaping step exists; `babyparse.unparse()` quotes the cell but does not neutralise formulas. An unrouted copy of the handler exists in `admin/server/api/download.js:70`.
- Every string that reaches a list field, from any writer, ends up in a cell. Keystone applications typically store data submitted by unauthenticated visitors (enquiry forms, comments, registrations) in lists that staff later export.

Additionally `value.toString()` throws on `null` and `undefined` cells, which aborts the whole export with a 500; the patch handles this case because it is on the same line.

## Impact

A party who can write a string into any field of an exported list can place a cell beginning with `+` in the CSV. When a staff member opens the export in a spreadsheet application that evaluates formulas and accepts the DDE or external-reference warning, the cell is evaluated in that user's context (data exfiltration via external references, command execution via DDE on configurations that still allow it). The victim is the operator's staff, not the Keystone server. The export endpoint itself is behind `keystoneAuth`, so the attacker does not need Admin UI access, only a way to get content stored.

CVSS rationale: PR:L assumes the writer is an authenticated user of the application; where unauthenticated input (for example a public form) is stored in an exported list the vector is PR:N and the score 5.1. UI:A because the staff member must open the export in a spreadsheet application and accept its warning. The impact lands on that user's workstation, scored as the subsequent system (SC:L, SI:L).

## Proof of concept

From the directory of an application that depends on `keystone` 4.2.1:

```
node -e "const e = require('keystone/lib/security/escapeValueForExcel'); console.log(JSON.stringify([e('=1'), e('-1'), e('@1'), e('+1')]))"
```

prints `[" =1"," -1"," @1","+1"]`: the first three values are prefixed with a space, the `+` value is not.

## Remediation

No upstream fix. The patch `PZSA-2026-004/0002-csv-export-escape-plus-prefix.patch` compares with `>= 0`, uses `String(value)` and passes `null` and `undefined` through untouched. One-line semantic change, same prefix-space strategy as the original fix.

Mitigations for operators:

- Apply the patch to `node_modules/keystone/lib/security/escapeValueForExcel.js`.
- Alternatively define `schema.methods.getCSVData` (hook at `lib/list/getCSVData.js:81`) or per-field `toCSV` transforms on exported lists to prefix `+` values yourself; the library's own pass runs afterwards and will not undo it.
- Restrict `export.csv` to trusted roles via a `pre:adminroutes` middleware, and open exports with formula evaluation disabled or in a text editor.
